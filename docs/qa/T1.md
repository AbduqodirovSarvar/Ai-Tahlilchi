## Topilmalar

### 🔴 F-1. Prod loglarida Telegram bot tokeni ochiq chiqadi
- **Joy:** `src/app/logging.py:45` (`structlog.processors.dict_tracebacks`) + `src/app/bot/dispatcher.py:15-19` (`exc_info=event.exception`).
- **Sabab:** structlog 26.1 da `dict_tracebacks` = `ExceptionDictTransformer(show_locals=True)`: har bir frame'ning lokal o'zgaruvchilari logga yoziladi. aiogram `AiohttpSession.make_request` ichida lokal `url = "https://api.telegram.org/bot<TOKEN>/sendMessage"` bor. Redaksiya faqat yuqori darajadagi kalit nomlariga qaraydi.
- **Takrorlash:** `python -m uv run pytest --runxfail tests/integration/test_secret_hygiene.py` → `'42:SUPERSECRET-TOKEN' is contained here: ...am.org/bot42:SUPERSECRET-TOKEN/sendMessage'`. Haqiqiy hayotda: Docker'da (`APP_ENV=prod`) admin `/start` yuborganda Telegram'ga ulanish uzilsa, token `docker compose logs` va json-file loglariga yoziladi.
- **Kutilgan:** token hech qachon logda yo'q. **Haqiqiy:** token 3 marta (`"url": "'https://api.telegram.org/bot42:...`).
- **Tuzatish (tekshirilgan):** `structlog.processors.dict_tracebacks` o'rniga `structlog.processors.ExceptionRenderer(structlog.tracebacks.ExceptionDictTransformer(show_locals=False))`. Probe bilan tasdiqlandi: token 0 marta, traceback tuzilmasi saqlanadi. Keyin 2 ta `xfail` belgisini olib tashlash kerak (strict: tuzatilgach testlar XPASS bo'lib yiqiladi).
- **Kimga:** infra-engineer.

### 🟡 F-2. Ichma-ich lug'atdagi maxfiy qiymatlar yashirilmaydi
- **Joy:** `src/app/logging.py:22-27`.
- **Takrorlash:** `get_logger(...).info("http_call", headers={"Authorization": "Bearer X"})` → JSON'da `"headers": {"Authorization": "Bearer X"}`. Test: `tests/test_logging.py::test_secrets_nested_in_mappings_are_redacted` (`xfail`).
- **Ta'sir:** hozir bunday chaqiruv yo'q, lekin F2.3 (API klient: `headers`, `params` da `x-apisports-key`) va F5.1 (Gemini) bunga olib keladi. F2 dan oldin rekursiv redaksiya tavsiya etiladi.

### 🟡 F-3. Redaksiya token hisobi kalitlarini ham yashiradi
- **Joy:** `src/app/logging.py:19,25` (`"token"` qismi).
- **Takrorlash:** `redact_secrets(None, "info", {"tokens_used": 120})` → `{"tokens_used": "***"}`.
- **Ta'sir:** F5.1/F5.5 Gemini token sarfini loglashi kerak (`prompt_tokens`, `tokens_used`): loglarda `***` bo'ladi. Ruxsat etilgan ro'yxat yoki aniqroq naqsh (`*_token`, `token` lekin `tokens_*` emas) kerak.

### 🟡 F-4. Noto'g'ri sozlama qiymati: exit 1 va xom traceback (exit 2 va JSON emas)
- **Joy:** `src/app/main.py:40` (`get_settings()` `try` dan va `configure_logging` dan oldin).
- **Takrorlash:** `docker run --rm --read-only --tmpfs /tmp -e TELEGRAM_BOT_TOKEN=42:FAKE -e ADMIN_IDS=abc ai-tahlilchi:qa` → `pydantic_core.ValidationError ... input_value='abc'`, `exit=1`.
- **Kutilgan (ADR 0001 §5 ruhida):** strukturali `startup_failed` log va `exit 2`. Bundan tashqari, `HEALTHCHECKS_URL` noto'g'ri bo'lsa, xato matnida URL (`input_value`) to'liq chiqadi (healthchecks UUID amalda secret).

### 🟡 F-5. `TZ` sozlamasi POSIX `TZ` muhit o'zgaruvchisi bilan to'qnashadi
- **Joy:** `src/app/config.py:49,73-82`.
- **Takrorlash:** `docker run --rm --read-only --tmpfs /tmp -e TZ=:/etc/localtime ai-tahlilchi:qa` → `TZ=':/etc/localtime' is not a known IANA time zone`, `exit=1`.
- **Ta'sir:** ba'zi hostlar/CI runner'lar `TZ` ni POSIX shaklida o'rnatadi: ilova ishga tushmaydi. Testlar endi `tests/conftest.py` da `TZ` ni tozalaydi, lekin ishlab chiqarishda xavf qoladi. Variant: `DISPLAY_TZ` nomi yoki `TZ` validatsiyasida aniq xabar bilan `ConfigurationError`.

### 🟡 F-6. Linux'da `./data` bind mount egasi root bo'ladi

- **Ta'sir (Windows'da takrorlanmaydi):** Linux VPS'da `./data` yo'q bo'lsa, Docker uni `root:root` bilan yaratadi; uid 10001 `/data/app.db` ga yoza olmaydi. F2 (SQLite) va F9 (deploy) dan oldin hal qilish kerak (named volume yoki `chown` qadami, RUNBOOK'da hujjatlash).
